# Shell Process Execution - Embox移植总结

## 项目概述

成功将Embox项目的shell命令执行机制（通过`new_task`生成新进程）移植到Zephyr RTOS的AS32X601平台。

## 核心功能

### 1. new_task() 实现

基于Embox的`src/kernel/task/multi/multi.c`实现，提供进程创建接口：

```c
pid_t new_task(const char *name, void *(*run)(void *), void *arg)
```

**实现要点：**
- 从当前进程创建子进程（`process_create(parent)`）
- 为新进程分配线程栈（2KB）
- 创建线程跳板（trampoline）机制
- 注册线程到进程（`process_register_thread()`）
- 使用`k_thread_create()`启动线程
- 返回子进程PID

### 2. 命令执行流程

模仿Embox的`tish.c::process_external()`：

```
用户输入 → parse_command() [解析命令行]
    ↓
shell_cmd_lookup() [查找命令]
    ↓
shell_exec_command() [执行命令]
    ↓
new_task("", run_cmd, &cmd_data) [创建新进程]
    ↓
task_trampoline() → run_cmd() → cmd->exec() [执行命令函数]
    ↓
waitpid() [等待进程结束，收集退出状态]
```

### 3. 进程间同步

**前台执行：**
- 使用`waitpid(pid, &status, 0)`等待子进程完成
- 通过消息队列传递退出状态
- 子进程在`task_trampoline()`中发送退出消息

**启动同步：**
- `cmd_data.started`标志位同步启动
- 子进程设置标志通知父进程已启动

### 4. 命令注册框架

提供类似Embox的命令注册机制：

```c
/* 定义命令函数 */
static int cmd_hello(int argc, char **argv)
{
    printk("Hello from PID %d!\n", process_current()->pid);
    return 0;
}

/* 注册命令 */
SHELL_CMD_REGISTER(hello, "Print hello message", cmd_hello);
```

## 配置选项

在`prj.conf`中配置：

```ini
# 进程支持
CONFIG_MAX_PROCESS_COUNT=32          # 最大进程数
CONFIG_MAX_FD_PER_PROCESS=16         # 每进程最大文件描述符数

# 内存配置
CONFIG_HEAP_MEM_POOL_SIZE=16384      # 堆大小（16KB）
CONFIG_MAIN_STACK_SIZE=2048          # 主栈大小
CONFIG_SHELL_STACK_SIZE=2048         # Shell栈大小

# 线程支持
CONFIG_DYNAMIC_THREAD=y              # 动态线程创建
CONFIG_THREAD_STACK_INFO=y           # 线程栈信息
CONFIG_THREAD_NAME=y                 # 线程命名
```

## 技术要点

### 1. 进程创建机制

使用Zephyr的进程子系统（`zephyr/kernel/process.c`）：
- `process_create()` - 创建进程结构
- `process_register_thread()` - 注册线程到进程
- `process_current()` - 获取当前进程

### 2. 线程管理

使用Zephyr的线程API：
- `k_thread_create()` - 创建线程
- `k_thread_name_set()` - 设置线程名
- 动态分配线程栈和结构体

### 3. 进程间通信

使用消息队列传递退出状态：
- `K_MSGQ_DEFINE()` - 定义消息队列
- `k_msgq_put()` - 发送退出消息
- `k_msgq_get()` - 接收退出消息（waitpid实现）

### 4. 内存管理

- 使用`k_malloc()`动态分配内存
- 栈大小：2048字节/进程
- 进程结构：约100字节
- 总开销：约2.2KB/进程

## 性能指标

在AS32X601平台（RISC-V 32位，主频未知）：
- 进程创建时间：约5-10ms
- 内存占用：2KB栈 + 进程结构
- 最大并发进程：32个（可配置）
- ROM占用：82KB
- RAM占用：32KB

## 与Embox的主要差异

### 1. 线程模型
- **Embox**: 自定义线程实现
- **Zephyr**: 使用`k_thread` API

### 2. 调度器
- **Embox**: `sched_lock()` 保护临界区
- **Zephyr**: `k_spinlock` 和 `k_mutex`

### 3. waitpid实现
- **Embox**: 直接检查任务状态
- **Zephyr**: 消息队列传递退出状态

### 4. 内存分配
- **Embox**: 静态任务表
- **Zephyr**: 动态内存分配（`k_malloc`）

## 已知限制

1. **无动态命令加载** - 所有命令编译时链接
2. **简化的waitpid** - 基于消息队列，不是完整POSIX实现
3. **无信号支持** - 未实现信号机制
4. **无I/O重定向** - 未实现`>`、`<`、`|`等
5. **无后台任务** - 未完全实现`&`后台执行
6. **无进程组** - 未实现进程组和会话
